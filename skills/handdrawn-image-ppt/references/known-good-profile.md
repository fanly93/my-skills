# 图片生成配置与已验证参数

原项目在 2026-10-13—14 成功完成过 10 页补充 PPT。这里保留可复用的调用参数和尺寸经验，不分发原项目专用的服务地址、模型别名或凭据授权。新任务使用当前用户指定且已授权的端点与模型；没有指定时优先使用 imagegen 的内置能力。

| 参数 | 已验证值 |
|---|---|
| 协议 | OpenAI 兼容 Image API |
| Base URL | 当前任务已授权的端点；通过 `BaseUrl` 或进程 `OPENAI_BASE_URL` 配置 |
| 图片模型 | 当前任务指定的可用图片模型；不把原项目别名设为通用默认值 |
| 调用实现 | bundled `image_gen.py` |
| 模式 | `edit`，输入统一风格图；有案例时再输入主题图 |
| 质量 | `high` |
| 尺寸 | `auto` |
| 格式 | PNG |
| 提示词处理 | `--no-augment`，完整文字和布局已在 prompt file 给出 |
| 实际输出 | 1672×941，10 页一致；接近 16:9，PPTX 为 1280×720 |
| 凭据来源 | 当前供应商已授权的进程环境变量；skill 不包含 key，也不继承历史项目授权 |

自定义模型别名曾受到 bundled CLI 的尺寸校验限制，`--size auto` 已实测成功。不要把这个经验推成“所有模型都只能 auto”；其他模型按其工具和官方支持的尺寸选择。

调用参考图来约束画风，比只说“手绘风格”更能保持多页一致。该 CLI 的 `edit` 是输入图片的 API 路径；新页提示词写明参考图只提供风格，不保留原文字。对错字或连线修正则用当前页为 edit target，另存修正版。

连续成功生成后仍发现过局部中文和箭头错误，因此高质量模型或成功返回并不能替代逐页目视检查。修正方法见 [局部修图](local-edit-examples.md)。

当前会话已有的授权对同一端点按其范围持续有效，无须重复向用户索要 key 或确认。历史项目的成功记录不构成当前任务授权，也不能据此把同一 key 自动发给新的第三方端点。
